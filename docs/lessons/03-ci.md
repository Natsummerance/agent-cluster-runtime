# 03-ci —— GitHub Actions / e2e-real

> 何时加载：改 CI、e2e 失败、端口冲突、缓存问题时**必读**。本模块是 token 消耗最大重灾区。

## e2e-real 端口竞态（反复失败的元凶，已根治）
- 现象：playwright 自起 serve 报 `Address already in use`；或探活 90s 假超时。
- 根因：
  1. playwright `webServer` 的 URL 探测是**单次检查**；后台 serve 冷启动未就绪时它自起 serve → 抢 8765。
  2. **探活必须带认证头**：`--auth-token ci` 下 `/api/v1/status` 返回 401，`curl -sf` 视为失败；
     playwright 的探测接受任意 HTTP 状态（401 也算就绪）——所以 playwright 侧 OK、curl 侧必须 `-H "X-Auth-Token: ci"`。
- 现行修复（勿回退）：`frontend/playwright.real.config.ts` 固定 `reuseExistingServer: true`；
  `ci.yml` e2e job 后台起 serve 后先 curl 探活（90s 循环 + 认证头）再跑 playwright；`trap cleanup EXIT` 杀进程树。

## 其他 CI 踩坑
- 嵌套 `pytest`（sandbox=None 的 QA 工具）需 `.venv/bin` 加入 `GITHUB_PATH`。
- CI worktree 初始提交需要 git identity：先 `git config --global user.name/email`。
- `setup-uv` cache 命中后 sync/run 快；node 依赖用 `actions/setup-node` + npm cache。
- macos-13 runner 排队 25min+ → 用 `macos-14`（同为 x64）。
- CI 失败排查顺序（省 token）：run 列表 → 失败 job 摘要（conclusion）→ 只拉失败 job 日志并用
  `Select-String` 过滤关键行（`FAILED|Timeout|error|##[error]`），**不要下载全量日志**。
- 失败日志钩子：三测试 job 已把输出落盘并在 `if: failure()` 上传 `diagnostics-*` artifact（保留 1 天），
  先看它再决定是否拉原生日志。
