**关键实现要点:**

## 风险清单（设计 §17 已裁定项不再列为风险）

1. **server.py 重构面最大（13.5/13.7/13.8/13.9 四次修改同一文件）**：`WorkbenchServer` 公开行为冻结是唯一防线的关键；13.5 的 `test_v05_serve_regression`（test_t12_3 原样不改）必须每任务门槛复跑。主线程在 13.5 与 13.7 提交后应重点复审 `_handle_sse` 与 `start_session` 的 diff。
2. **SSE/WS 双通道 seq 一致性**：`session.end` 哨兵是前端唯一终态判定；`id:`、WS `event.seq`、`SessionEventLog.append` 返回值必须同源。13.7/13.8/13.10 三任务不得各自造 seq。主线程复审点：13.10 的 `sseReducer` 去重函数被 wsClient 复用。
3. **执行顺序风险**：13.6 的 deterministic-accept 是 13.15 e2e-real 能无人值守跑通的前提；13.5 的 shutdown 修复是 CI `e2e-real` job `finally` kill 有效的前提。任何试图把 13.15 提前到 13.6/13.5 之前的排程都会导致 CI 挂死或误报，主线程不得放行。
4. **打包矩阵环境风险**：macOS/Linux 本机无法验收，只能靠 CI 构建物；arm64 NSIS 交叉构建依赖 electron-builder 网络拉取 arm64 Electron 二进制，失败需重试（非代码问题）。13.16 真机验收是 Windows 唯一验收口径，不可用「CI 绿」替代。
5. **计划新增的两处实现裁定（设计文档未覆盖，已在任务中写死，后续不得重新打开）**：(a) 浏览器 WebSocket 无法携带 `X-Auth-Token` 头 → 13.8 增加 `token` 查询参数等价通道（头优先）；(b) fork 产物为「待启动」会话（status 记录 active、线程为空），`session.start` 事件在派生时写入新会话事件日志，启动走 `session_id` 恢复路径。
