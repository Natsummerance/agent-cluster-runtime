# 2025–2026 商业 AI 编码代理竞品调研报告
**为 agent-cluster-runtime v0.6.0 规划提供的竞品依据**

> 调研截止 2026-08-13。可信度：**高** = 厂商官方一手（官方页面/文档/博客）；**中** = 官方发布经媒体转载；**低** = 社区仓库/第三方汇总。单一来源均标注「未交叉验证」；无证据处标注「数据不足」，不推断。

---

## 维度 1：项目级 / 多任务管理

- **GitHub Copilot Agents（2025-10-13）**：官方功能页明确提供统一任务面板——原文 "Manage agents and tasks together"，可同时监控多个 coding agent 任务；支持从 GitHub Issues、Azure Boards、Jira、Raycast、Linear 直接指派，也可在 Slack/Teams 聊天中下发任务。FAQ 确认 agent 任务同时消耗 GitHub Actions minutes 与 AI Credits（计量与任务直接挂钩）。【高】[github.com/features/copilot/agents](https://github.com/features/copilot/agents)
- **OpenHands Agent Control Plane（2026-05-05）**：推出企业级控制平面，支持跨仓库、跨团队并行运行 workflows，内置调度、重试与状态管理，且 "usage and spend are tracked at the workflow level"。【中，未交叉验证】[tmcnet.com 发布稿](https://www.tmcnet.com/usubmit/2026/05/06/10378085.htm)
- **Devin 2.0（2025-04-02）**：官方博客确认可 "spin up multiple parallel Devins"，并配套交互式云端 IDE；2.x 系列延续并行会话路线。【高】[cognition.ai/blog/devin-2](https://cognition.ai/blog/devin-2)
- **OpenAI Codex（2026-02）**：macOS 桌面 app 支持 Git worktrees、按项目组织 threads、并行运行多个 agents，并加入 automations/schedules 定时任务（heise.de 2026-02-03 与 engineering.fyi 2026-02-01 报道；后者页面已 403）。【中，未交叉验证】
- **OpenAI Codex `/orchestrate`（2026-05-14）**：openai/codex 讨论区 issue #22749 显示可协调 child agents 并设 review gates。【低，仅搜索摘要、页面未完整读取，未交叉验证】
- **Factory Droid GA（2025-05-27）**：GA 公告把头牌能力定位为 "Automated Linear Management"——从 Linear issue 自动拆解、执行并开 PR。【高】[factory.ai/news/factory-is-ga](https://factory.ai/news/factory-is-ga)
- **Cursor / Windsurf**：2026 年仍以单 agent IDE 为核心（Cascade 等），未见项目级看板/跨任务并行的一手证据 → **数据不足**，仅作对比参照。

**对 v0.6.0 的启示**
- 把「任务面板 + 多 agent 并行 + workflow/项目归属」做成一等公民：参照 Copilot Agents 的"从 issue/ticket 指派"，v0.6.0 的编排入口应接到工单系统，而非只有 CLI。
- 并行度需要两级抽象：项目内多 agent（Devin/Codex 路线）+ 组织级跨仓库 workflow（OpenHands Control Plane 路线），并让成本、状态、重试都挂到 workflow 上。
- 任务依赖/子代理评审门方面，`/orchestrate` 是唯一公开证据点但证据薄弱——建议自研依赖图 + 审批门，不照搬。

## 维度 2：CI 集成

- **GitHub Copilot coding agent（2025-05-19）**：官方设计为「agent 生成 PR 后必须先经人工批准，CI/CD 才会触发」——人审是 CI 的硬前置闸门（IT Brief / VAR India 转载官方发布）。【中，未交叉验证】
- **Devin × GitHub Actions（2025 年中）**：社区已有 GitHub Actions 集成与 PR 冲突自动解决工作流（如 `aaronsteers/devin-action`；calcom/cal.diy 仓库用 Devin 解决 PR 冲突）。【低，未交叉验证】[github.com/aaronsteers/devin-action](https://github.com/aaronsteers/devin-action)
- **OpenHands resolver（2025-04）**：官方仓库提供 `openhands-resolver.yml` GitHub Actions 工作流，把 issue 自动修复跑成 CI 任务（agent 开 PR）。【高】[github.com/All-Hands-AI/OpenHands](https://github.com/All-Hands-AI/OpenHands)
- **Factory Droid（2025-10 前后）**：官方文档提供 GitHub/GitLab code review Actions（Droid 自动 review PR）。【中，未交叉验证】[docs.factory.ai](https://docs.factory.ai)
- **OpenAI Codex（2025-10）**：官方 cookbook 提供 Codex SDK 的 CI 集成示例，另发布 `openai/codex-action`，走"审查 + 自动修"路径。【中，未交叉验证】[cookbook.openai.com](https://cookbook.openai.com)

**对 v0.6.0 的启示**
- 行业共识是「agent PR 不自动进 CI/CD」：v0.6.0 应把"人工审批 → CI 触发 → 失败自动重试修复"做成可配置默认管道，对齐 Copilot 的安全默认值。
- 至少提供第一方 GitHub Actions 适配层（对标 devin-action / openhands-resolver / codex-action），否则企业不敢让 agent 写 PR。
- 冲突解决与自动 review 是两个高价值切口，可作为 v0.6.0 的 CI 差异化能力。

## 维度 3：成本与用量

- **Devin（官方企业计费文档）**：Enterprise 按 ACU 计费；提供企业级 + 组织级两级 Consumption 面板；可设 **per-Organization ACU 硬上限，达限即停**。【高】[docs.devin.ai/admin/billing/enterprise](https://docs.devin.ai/admin/billing/enterprise)
- **OpenAI Enterprise Analytics（2026-06-18）**：统一 admin 看板集中展示 ChatGPT 与 Codex 的 credit 消耗，可按用户、产品、模型切分（Channel NewsAsia 报道）。【中，未交叉验证】另有 2026-06-29 相关事件说明表明 Codex 使用限额在 dashboard 以百分比展示。【未交叉验证】
- **GitHub Copilot（2026-02 / 2025-11）**：usage metrics 于 2026-02 正式 GA，2025-11 增加 fine-grained 权限；AI Credits 仪表盘 + premium requests 分层计费。【高（官方 changelog）】[github.blog/changelog](https://github.blog/changelog/)
- **Claude Code（Anthropic）**：Console 提供会话消费记录与 workspace spend limits；官方口径为平均 $6/天、90% 用户 <$12/天（2026 年报道，未交叉验证）；社区有 ccusage/OTel 成本看板补充。【中–低】[console.anthropic.com](https://console.anthropic.com)
- **OpenHands Control Plane（2026-05-05）**：明确 "usage and spend are tracked at the workflow level"——用量治理绑定到编排单元。【中，未交叉验证】[tmcnet.com 发布稿](https://www.tmcnet.com/usubmit/2026/05/06/10378085.htm)
- **Cline（2025 社区）**：Usage Analytics 仅处于 issue 提案阶段（issue #4540），落后于上述商业化产品。【低，未交叉验证】[github.com/cline/cline/issues/4540](https://github.com/cline/cline/issues/4540)

**对 v0.6.0 的启示**
- 预算控制要做成「硬闸门」：Devin 的组织级 ACU 达限即停是标杆；v0.6.0 的 quota 不应只是通知，而应支持停任务/排队。
- 成本归属与编排对齐：OpenHands 的 workflow 级 spend、Copilot 的"任务双计量（Actions + AI Credits）"都说明用量必须按任务/项目归集，v0.6.0 成本仪表盘应内建该维度。
- 企业分析看板（跨用户/产品/模型，对标 OpenAI Enterprise Analytics）是 v0.6.0 管理端的最小可交付功能。

## 维度 4：企业集成实连

- **GitHub Copilot**：Linear 集成于 2025-10-27 进入 public preview；官方功能页确认可从 Linear/Jira/Azure Boards/Raycast 指派、从 Slack/Teams 下发任务。【高】[github.com/features/copilot/agents](https://github.com/features/copilot/agents)
- **Cognition Devin**：2.1 公告（2025-05-14）实连 Linear 与 Jira（可批量请求 confidence scores 而不启动 session）；另集成 Slack、Datadog、Sentry，多来源交叉确认。【高（官方公告，具体链接未存档）】
- **Factory.ai**：agent 可直接运行在 Slack/Linear/浏览器；集成 Jira、Datadog、Google Drive；2025-10 上线 AWS Marketplace 私有定价（EDP）。【高（GA 公告）+ 扩展项未交叉验证】[factory.ai/news/factory-is-ga](https://factory.ai/news/factory-is-ga)
- **OpenHands**：enterprise 文档提供 webhook 式 Slack/Jira 集成；2025-11 官方 Slack 集成进入 beta。【中，未交叉验证】[github.com/All-Hands-AI/OpenHands](https://github.com/All-Hands-AI/OpenHands)
- **Claude Code**：官方 knowledge-work-plugins 仓库提供 Slack/Linear/Jira/Notion 连接器，其余靠 MCP 自装。【高（官方仓库），插件清单细节未交叉验证】[github.com/anthropics/claude-code](https://github.com/anthropics/claude-code)
- **Amp（Sourcegraph）、bolt.new / Lovable**：未收集到 2025-06 之后 Jira/Linear/Slack 实连的一手证据 → **数据不足**。

**对 v0.6.0 的启示**
- Linear 是 2025–2026 编码 agent 的集成第一站（Copilot/Devin/Factory/OpenHands 全有），v0.6.0 应优先做 Linear 连接器，再补 Jira 与 Slack。
- 最有价值的模式不是"读 issue"，而是 Devin 的 confidence scores（不启动 session 先打分）与 Factory 的 Automated Linear Management（闭环到 PR）——v0.6.0 可把「评估 → 指派 → 执行 → 回写」做成原语。
- 集成面建议走 webhook/事件驱动（OpenHands 路线），避免与每家 SaaS 深度绑定。

## 维度 5：实时交互与 HITL

- **OpenAI Auto-review（2026-04-29）**：专门的 reviewer agent 替代人工审批，宣称人类审批次数减少约 200 倍、边界动作 99% 自动批准；通过 `sandbox_mode`、`config.toml`、`.rules` 控制，官方原文同时披露了代价与局限。【高】[alignment.openai.com/auto-review](https://alignment.openai.com/auto-review/)
- **Devin Interactive Planning（2025 年）**：执行前先给人类 review roadmap（pre-execution 审批点）。【中，未交叉验证】
- **GitHub Copilot coding agent**：PR 人工审批是 CI/CD 的硬前置闸门（见维度 2，2025-05-19）。【中，未交叉验证】
- **Claude Code**：`/checkpoint`、`--resume`、命名 session、`--fork-session` 构成断点/分支续跑能力（官方文档；另有 2025-12 第三方汇总佐证）。【中，未交叉验证】[code.claude.com/docs](https://code.claude.com/docs)
- **通用实时打断**：除 Codex 云端会话与 Devin IDE 的交互式接管外，未找到 2025-06 后"通用实时打断协议"的公开一手文档 → **部分数据不足**。

**对 v0.6.0 的启示**
- 2026 年 HITL 前沿已从"每步人工审批"转向"自动 reviewer + 边界审批门"（OpenAI Auto-review）：v0.6.0 值得内置 reviewer agent，人工只看边界动作。
- 审批门要可编程（`config.toml`/`.rules` 风格）而非写死；同时保留 sandbox_mode 类环境隔离旋钮。
- 断点续跑/会话分叉（checkpoint/resume/fork）应作为 v0.6.0 runtime 的核心原语，而非补丁功能。

**对 v0.6.0 的启示**
- 定价共识已收敛为「低月费订阅 + 用量单位（ACU/credits/premium requests）超额计费」：v0.6.0 计费抽象应支持订阅、用量双轨，并在用量维度设硬上限。
- 形态上「云端编排 + 本地执行」（Codex worktrees、Claude 本地 CLI + OpenHands 云端控制面）是 2026 主流；v0.6.0 应把「本地 worker 接入云端 cluster」当作默认部署模式之一。
- 企业定价普遍转向 seats + 私有部署（VPC/自托管/AWS Marketplace），v0.6.0 企业版应预留部署形态与结算通道的抽象。

## 最强竞品清单（按「项目层管理 + 企业集成成熟度」排序）

1. **GitHub Copilot coding agent / Agents**——唯一原生绑定 Issues/Actions 生态：统一多 agent 面板 + Linear/Jira/Slack 指派 + CI 审批闸门 + AI Credits 治理，项目层与企业集成最完整。
2. **Cognition Devin（2.x/Enterprise）**——并行多 Devin + 组织级 ACU 硬上限与两级用量面板 + Linear/Jira/Slack/Datadog 实连 + GitHub Actions 集成，企业治理深度第一梯队。
3. **OpenHands + Agent Control Plane（2026-05）**——跨仓库并行 workflow、调度/重试/状态管理 + workflow 级 spend 追踪；开源底座使其成为可内嵌的控制平面参照。
4. **Factory.ai Droid**——Automated Linear Management 端到端闭环 + Slack/浏览器运行 + 企业 seats/AWS Marketplace；工作流自动化成熟度高，生态广度略逊前三。
5. **OpenAI Codex**——云端并行 + macOS 工作台（worktrees/定时任务）+ Enterprise Analytics 统一用量看板；治理强，但 Jira/Linear 原生指派仍弱于前四。
- Runner-up：**Claude Code**——本地终端形态 + MCP/插件生态最开放，但项目看板与组织级用量治理依赖 Console 与第三方，未形成完整项目管理层。
