## 2. 术语与目标

**术语**

- **项目层（Project layer）**：以「项目」为容器的产品层抽象：一个项目 = 多个工作区（workspace）+ 多个会话（session）+ 一个预算池（budget pool）+ 一套门策略。
- **会话（Session）**：一次 build 运行（v0.5 已有），由 SessionRecord（状态）、FileCheckpointer（thread_id 持久游标）、TokenLedger（账本）构成。
- **预算池（Budget pool）**：项目级硬上限与阈值预警的静态分配模型（§5）。
- **任务面板（Task panel）**：项目内会话的可指派/可筛选列表（Copilot Agents 式）。
- **自动 reviewer**：常规门由 LLM 自动评审、仅边界动作升级人工的门策略（§9）。
- **协议级消息**：WebSocket JSON 帧中的 cancel/approval/interrupt 等控制消息（§6.4）。
- **fork-session**：从既有会话的 checkpoint 派生新会话（§7）。

**目标（决策 8 成功标准，本轮无工期硬约束）**

1. 从单会话产品构建升级为多会话项目管理：项目=多会话+预算池，会话可 fork、可并发、可聚合观测。
2. 具备跨平台分发能力：Windows NSIS（x64+arm64）、macOS（arm64+x64，签名预留）、Linux deb（单格式），配自动更新双通道。
3. 具备持续交付能力：repo CI（pytest+Vitest+Playwright 真实后端）+ tag 触发打包发布 + 第一方 Actions 模板。
4. 本轮范围冻结（决策 3）：企业集成≈云端化≈OAuth MCP 合并为 **v0.7 主史诗**（不在本轮）；完整 PPM 拆 **v0.7+**（不在本轮）；WebSocket **本轮做**、仅作产品内通道；不做 BATS 预算注入推理（决策 11）。

## 3. 项目层数据模型

### 3.1 模型定义（全部 pydantic v2）

新模块 `src/agent_cluster/projects.py`：全部模型用 `from pydantic import BaseModel, ConfigDict, Field`，`model_config = ConfigDict(extra="ignore")`，复杂字段带 `Field(description=...)`。

```python
class BudgetUnlockRecord(BaseModel):
    """一次预算池解锁的审计记录（自服务解锁与例外审批共用）。"""

    model_config = ConfigDict(extra="ignore")

    id: str = Field(default_factory=lambda: uuid.uuid4().hex, description="解锁记录 id")
    session_id: str = Field(default="", description="触发解锁的会话 id（空=项目级操作）")
    additional_tokens: int = Field(gt=0, description="申请追加的 token 数")
    reason: str = Field(default="", description="解锁理由（非空语义由 API 层校验）")
    status: Literal["granted", "pending", "denied"] = Field(default="granted", description="解锁状态")
    created_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc), description="申请时间")
    decided_at: datetime | None = Field(default=None, description="审批决策时间（仅 pending 流转时写入）")
    decided_by: str = Field(default="self", description="决策者：self 或审批人标识")


class BudgetPoolRecord(BaseModel):
    """项目级预算池：静态分配（会话独立预算延续现状 + 项目硬上限与阈值预警）。"""

    model_config = ConfigDict(extra="ignore")

    hard_limit_tokens: int = Field(default=0, ge=0, description="项目硬上限 token（0=不设限；与 TokenLedger 的 budget>0 判定约定一致）")
    warn_ratio: float = Field(default=0.8, gt=0.0, le=1.0, description="预警阈值比例：项目已用 >= hard_limit×warn_ratio 触发 budget.warning")
    warn_reenable_ratio: float = Field(default=0.7, gt=0.0, le=1.0, description="预警滞回解除比例：已用回落到该比例以下才允许再次预警")
    unlock_requires_approval: bool = Field(default=False, description="解锁是否需人工审批（例外开关；False=自服务直接生效）")
    unlocks: list[BudgetUnlockRecord] = Field(default_factory=list, description="解锁审计记录（append-only）")
    warn_raised: bool = Field(default=False, description="预警是否已触发（滞回防抖状态）")
    last_warned_at: datetime | None = Field(default=None, description="最近一次预警时间")


class GatePolicyConfig(BaseModel):
    """自动 reviewer 门策略（内嵌 project.json，可经 API 局部覆盖）。"""

    model_config = ConfigDict(extra="ignore")

    auto_review: bool = Field(default=True, description="启用自动评审；False=回到 v0.5 ask 人工模式")
    auto_kinds: list[str] = Field(
        default_factory=lambda: ["design_review", "code_review", "iteration_acceptance"],
        description="自动评审白名单（常规变更门类别）",
    )
    human_kinds: list[str] = Field(
        default_factory=lambda: ["requirement_confirmation", "release", "dangerous_tool", "evolution_apply"],
        description="恒人工黑名单（边界动作门类别）",
    )
    review_confidence_threshold: float = Field(default=0.7, gt=0.0, le=1.0, description="自动评审置信度低于该值升级人工")
    rework_escalation: int = Field(default=DEFAULT_REWORK_LIMIT, gt=0, description="返工上限：同门 reject/edit 累计达到即升级人工（与 rework_limit 同语义）")
    review_prompt: str = Field(default="", description="自动评审提示词覆盖（空=内置默认）")


class SessionIndexEntry(BaseModel):
    """项目会话注册表条目（任务面板与项目聚合的数据源；运行时状态以 ServerSession 为准）。"""

    model_config = ConfigDict(extra="ignore")

    session_id: str = Field(description="会话 id")
    goal: str = Field(default="", description="会话目标")
    status: Literal["active", "completed", "aborted"] = Field(default="active", description="会话终态（与 SessionRecord.status 一致）")
    assignee: str = Field(default="", description="任务面板指派（空=未指派）")
    workspace: str = Field(default="", description="会话工作区绝对路径（worktree 开启时为检出路径）")
    worktree: bool = Field(default=False, description="是否运行在隔离 worktree")
    created_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc), description="创建时间")
    updated_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc), description="更新时间")
    metadata: dict[str, str] = Field(default_factory=dict, description="可过滤元数据（对标 LangSmith threads 的 metadata 过滤）")


class ProjectRecord(BaseModel):
    """项目容器：多工作区 + 多会话 + 预算池 + 门策略。"""

    model_config = ConfigDict(extra="ignore")

    project_id: str = Field(description="项目 id（uuid4().hex[:12]，沿用 v0.5 格式）")
    name: str = Field(min_length=1, description="项目名")
    description: str = Field(default="", description="项目描述")
    workspaces: list[str] = Field(min_length=1, description="工作区绝对路径列表（首项为主工作区，为集成/合并目标）")
    default_flow: str = Field(default=DEFAULT_FLOW, description="新建会话默认流程 YAML 路径")
    status: Literal["active", "archived"] = Field(default="active", description="项目状态")
    budget_pool: BudgetPoolRecord = Field(default_factory=BudgetPoolRecord, description="项目预算池")
    gate_policy: GatePolicyConfig = Field(default_factory=GatePolicyConfig, description="门策略（自动 reviewer 配置）")
    sessions: list[SessionIndexEntry] = Field(default_factory=list, description="会话注册表（索引；账本/阶段等权威数据在各会话 session.json）")
    metadata: dict[str, str] = Field(default_factory=dict, description="项目元数据（过滤/归类）")
    created_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc), description="创建时间")
    updated_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc), description="更新时间")
```

## 4. 存储迁移

### 4.1 触发时机（唯一结论）

- `ProjectStore.create_project(workspace=W)`：W 下存在 `<W>/.agent-cluster/session.json` 且有效 → 立即迁移为该项目首个会话。
- `WorkbenchServer.start_session(pid, spec)`：惰性兜底——项目会话目录缺失、但项目任一工作区仍存在未迁移的 v0.5 session.json 时，先执行迁移，再决定新建/恢复。
- CLI `build`（无项目上下文）与直接库调用：**不触发迁移**，继续使用 `<workspace>/.agent-cluster/session.json` 旧路径。实现方式：`SessionStore` 构造新增可选参数 `project_id: str | None = None`（纯增量）；传 `project_id` 时解析到项目会话目录，否则行为与 v0.5 完全一致——SessionDriver 既有测试与用法零改动。

### 4.2 迁移算法（无损、幂等、失败回退）

输入：`project_id`、`workspace`。步骤：

1. **幂等短路**：`<W>/.agent-cluster/.migrated.json` 存在且其 `session_id` 对应的 `projects/<pid>/sessions/<sid>/session.json` 存在 → 直接返回该会话。
2. 读取 `<W>/.agent-cluster/session.json`；缺失/损坏 → 不迁移、返回 None（与 v0.5「损坏即新会话」的容错语义一致）。
3. `SessionRecord.model_validate(data)`；`sid = record.session_id`；经 `model_copy(update={"project_id": pid})` 生成目标记录（不改写源文件）。
4. **备份先行**：把源文件复制到 `<W>/.agent-cluster/backups/session.v0.5.<UTC时间戳>.json`（备份永远先于任何新位置写入）。
5. 原子写入 `projects/<pid>/sessions/<sid>/session.json`。
6. 复制 checkpoints：`<W>/.agent-cluster/checkpoints/<thread_id>.json` → `projects/<pid>/sessions/<sid>/checkpoints/<thread_id>.json`（thread_id 持久游标不断，resume 可用）。
7. **记忆合并**：workspace 级记忆的 session/project 层按 item id 幂等合并进 `projects/<pid>/memory/`；gotcha/domain 层合并进全局 `~/.agent-cluster` 记忆库；源文件保留不删除。
8. 写标记 `<W>/.agent-cluster/.migrated.json`：`{"migrated_at": ..., "project_id": ..., "session_id": ..., "source": "session.json"}`。
9. 在 `ProjectRecord.sessions` 登记 `SessionIndexEntry`（status 取 record.status、goal 取 record.goal）。

- **失败回退**：第 4–9 步任一步抛异常 → 记录 `[migration]` 警告日志（不向调用方抛出），源文件与源目录零改动，返回 None；调用方按「无历史会话」继续（新建）或按 spec 报错。因未写标记，下次调用自动重试（可恢复）。
- **无损**：迁移过程永不删除、永不改写 `<W>/.agent-cluster/session.json` 本体；checkpoint/记忆均复制合并。
### 4.3 记忆 SQLite 与 checkpoint 的共享只读方案（决策 12）

- **项目记忆库**（SQLite + Markdown 四级结构不变）：
  - 读：任意会话、任意 API 随时可读（并发安全）。
  - 写：仅经 `MemoryStore` 公开方法（`add_candidate/promote/save_session_summary/...`），在 `ProjectStore` 级 `threading.Lock` 下串行；运行中的会话对记忆**只读**，写入只发生在门决策、会话结束、API 调用等生命周期边界。
  - SQLite 打开参数固定：`PRAGMA journal_mode=WAL`、`PRAGMA busy_timeout=5000`、`PRAGMA synchronous=NORMAL`（跨会话读不阻塞写、跨进程不互锁）。
- **checkpoints**：每 `thread_id` 一个 JSON 文件；会话只写自己的线程文件，绝不读写其他线程文件；fork 是唯一允许的跨会话读（复制语义，§7）。
- **账本**：每会话 `session.json` 内嵌 TokenLedger，仅本会话线程写；项目聚合只读所有会话账本求和（§5.1）。
- **一句话结论（共享读/写边界）**：多会话共享的一切资源（记忆库、聚合账本、checkpoint 源）**只读**；写路径要么归单一所有者（会话文件、线程 checkpoint），要么经项目级锁串行（project.json、记忆库）。主工作区是唯一集成点，并发会话不直写（§8.2）。

## 5. 预算池语义

### 5.1 字段与归属（决策 11）

- **会话独立预算**：`SessionRecord.budget`（创建时由 spec 给定或 `estimate_budget` 建议），延续 v0.5 现状——静态分配，不随项目池动态切分。
- **项目硬上限与预警**：`BudgetPoolRecord.hard_limit_tokens / warn_ratio / warn_reenable_ratio / unlock_requires_approval`（§3.1）。默认 `hard_limit_tokens=0`（不设限），用户经项目设置/API 开启。
- **归因**：权威归因 = 各会话 `TokenLedger` 按 `session_id` 求和（`ProjectStore.aggregate_used_tokens`）；project.json 不冗余存储用量（防止漂移）。
- **不做 BATS 预算注入推理**：剩余预算不注入 agent 推理循环（综合调研 §2 的 Google Budget Tracker/BATS 属进阶研究，不列入 MVP）。

### 5.2 判定顺序（唯一结论）

按以下顺序执行，命中即停（前一条不阻断后一条的审计记录）：

1. **会话级**（每次 `usage_hook` 记账后）：`ledger.over_budget()` → 沿用 v0.5 行为：挂起并升级人工（继续/缩减/结束）。既有判定，不改。
2. **项目预警**（`budget_pool_hook` 聚合后）：`hard_limit > 0` 且 `project_used >= hard_limit × warn_ratio` 且 `warn_raised=False` → 置 `warn_raised=True`、发 `budget.warning` 事件；当 `project_used < hard_limit × warn_reenable_ratio` 时复位 `warn_raised=False`（滞回防抖）。
3. **项目硬上限**（聚合后）：`hard_limit > 0` 且 `project_used > hard_limit` → 发 `budget.exhausted` 事件；对**运行中会话在下一个门/挂起点挂起**（不杀进程、checkpoint 保留）；**新建会话被拒绝**（`POST /projects/{pid}/sessions` 返回 409 + code `budget_pool_exhausted`）。
4. **解锁后**：硬上限提高后，挂起会话由用户继续，新建恢复允许。

### 5.3 超限解锁流程（对齐 Databricks：自服务解锁、审批只留给例外）

- **默认自服务**：`POST /api/v1/projects/{pid}/budget/unlock` `{additional_tokens > 0, reason 非空}` → 直接 `hard_limit_tokens += additional_tokens`，追加 `BudgetUnlockRecord(status="granted", decided_by="self")`，发 `budget.unlocked` 事件，返回 200。审计 append-only，永不删除。
- **例外审批**：`unlock_requires_approval=True` 时同一端点返回 202、记录 `status="pending"`（不改变硬上限）；审批入口 `POST /api/v1/projects/{pid}/budget/unlock/{unlock_id}/approve` 与 `/deny`（复用 X-Auth-Token 认证，操作人写入 decided_by）。只有 pending 记录可被决策。
- 解锁与「会话独立预算」互不影响：解锁只提高项目硬上限，不重置、不追加任何会话账本。

### 5.4 与 TokenLedger 的挂接（红线：TokenLedger 模型零改动）

- `SessionDriver` 新增可选 kwarg `budget_pool_hook: Callable[[SessionRecord], None] | None = None`；`usage_hook` 在 `self.store.save()` 之后调用 hook（传本会话 record）。
- hook 由 `SessionManager` 注入，职责：更新内存聚合缓存 + 执行 §5.2 判定 2/3 + 向事件总线发事件。
- 聚合值只存内存（`SessionManager._used_cache[pid]`）；进程重启后首次读取全量扫描会话账本重建。
- `TokenLedger` 及 `record/total/remaining/over_budget/phase_used/phase_budget/phase_over_budget/by_role/by_phase/estimate_accuracy/summary` 全部保持不变。

### 6.3 SSE 事件扩展与三异常态修复（决策 15）

- 端点不变：`GET /api/v1/sessions/{sid}/events?since=N`。
- **扩展**：每个事件写 `id: <seq>` 行（`Last-Event-ID` 续传依据）；连接建立时先发 `retry: 3000`；心跳从 20s 收紧为 15s（`: ping` 注释行）；会话终结时在重放后发**终止哨兵** `event: session.end`，`data: {"type":"session.end","status":"completed|failed|cancelled","seq":N}`，随后关闭连接（与既有「已结束会话重放后关闭」合并为同一路径）。
- 新事件类型：`budget.warning / budget.exhausted / budget.unlocked / session.forked / stdin.applied / review.auto_decision / session.cancel / session.end`（均带 `session_id`，沿用现有事件日志结构）。
- **三异常态修复（唯一结论）**：
  1. **挂起无超时**：客户端 30s 未收到任何字节（含 ping）→ Abort 并按重连策略重连；服务端 15s 心跳保证未挂死连接可被双方检出；写失败（BrokenPipe/ConnectionReset）即退出订阅（既有行为保留）。
  2. **静默中止**：会话线程结束/崩溃路径必须先在 `finally` 兜底写入 `session.end` 哨兵再关 SSE；客户端只有收到哨兵才允许把会话标为终态，否则视为断线进入重连。
  3. **掉线重连**：前端 `subscribeSse` 升级为自动重连（指数退避 1s→2s→4s，上限 15s，活跃会话无限重试）；重连请求带 `Last-Event-ID`（优先）与 `?since=`（回退），服务端按 seq 重放缺口；`sseReducer` 按 seq 去重——事件不丢、不重。

### 6.4 WebSocket 消息协议（决策 15：产品内双向通道）

- **传输与握手**：与 HTTP 同端口、同认证；`GET /api/v1/ws?session_id=<sid>`，`X-Auth-Token` 校验失败 → HTTP 401 不升级。实现为基于 stdlib `ThreadingHTTPServer` 的**自研最小 RFC 6455 帧编解码**（握手 SHA-1 accept-key、text/ping/pong/close 帧、文本帧 ≤64KiB），不引入第三方依赖；不引入任何 MCP 传输语义（WS 仅产品内通道，SSE 保留回退）。
- **帧 schema**（JSON 文本帧；`id` 为请求方相关 id，服务端原样回填）：

```jsonc
// 客户端 → 服务端
{"type":"subscribe","id":"c1","payload":{"session_ids":["<sid>"]}}   // 空列表/缺省 = 项目与全局事件
{"type":"ping","id":"c2","payload":{}}
{"type":"cancel","id":"c3","payload":{"session_id":"<sid>"}}
{"type":"approval","id":"c4","payload":{"session_id":"<sid>","decision":"approve|reject|edit|response","text":"..."}}
{"type":"interrupt","id":"c5","payload":{"session_id":"<sid>","text":"..."}}
{"type":"stdin","id":"c6","payload":{"session_id":"<sid>","text":"..."}}

// 服务端 → 客户端
{"type":"ack","id":"c1","payload":{"ok":true}}
{"type":"snapshot","id":"c2","payload":{"project":"<pid>","dashboard":{...},"sessions":[...]}}  // subscribe 后回放
{"type":"event","seq":42,"session_id":"<sid>","payload":{...}}       // 与 SSE data 同构
{"type":"error","id":"c4","payload":{"code":"not_found|session_busy|bad_frame|unknown_type","message":"...","fatal":false}}
{"type":"pong","id":"c5","payload":{}}
```

- **协议级三消息**：`cancel/approval/interrupt` 与 REST 端点 1:1 映射（同一 ServerSession 线程安全队列与校验），成功后回 `ack`；`stdin` 语义同 §11。
- **错误处理**：未知 `type` → `error(unknown_type)` 不关连接；非法 JSON → `error(bad_frame)`，连续 3 次坏帧 → close code 1002；目标会话不存在/已终态 → `error(not_found/session_busy)` 不关连接；服务端主动关连接前必发 close 帧（1000/1001）。
- **回退策略**：前端 `wsClient` 握手失败（非 101）或帧通道异常时自动回退 SSE+REST（全部协议消息均有 REST 等价端点）；SSE 与 WS 可并存，双通道去重由 `seq` 保证。

## 7. fork-session 语义（决策 2：并入项目层）

- **入口**：`POST /api/v1/sessions/{sid}/fork` + 会话详情页「派生会话」按钮。CLI 单机 build 无项目上下文，不提供 fork（项目层专属能力）。
- **派生规则（唯一结论，覆盖任意源状态）**：
  - 源 `completed` → 允许派生；
  - 源 `aborted` → 允许派生（从最后 checkpoint 继续）；
  - 源 `active`（含 waiting_approval）→ **409 + code `fork_conflict`**（运行中 checkpoint 非稳定态，禁止派生；先 cancel 至 aborted 再派生）。
- **前置校验顺序**：源会话存在 → 状态允许 → `fork_depth + 1 <= 5`（超限 409，防分叉爆炸）→ 项目预算硬上限未耗尽（§5.2，耗尽则 409）。
- **派生产物（唯一结论）**：
  - 新会话 `session_id=uuid4().hex[:12]`、**新 `thread_id=uuid4().hex`**：checkpoint 复制后两会话历史从复制点独立演化、互不影响；`parent_session_id` 记录血缘，`fork_depth=源+1`。
  - **checkpoint 复制策略**：把源 `checkpoints/<src_thread>.json` 原样复制为 `checkpoints/<new_thread>.json`（含 `writes` 中途写，resume 可从中断点续跑）；源文件只读不删。
  - **产物/PRD 继承**：默认 `worktree=true`——从源会话合并回主工作区后的 HEAD 切出 `acs/fork/<sid>` 检出（继承全部产物与 PRD）；`goal` 默认=源 goal，可覆盖。
  - **transcript**：不复制源 transcript，追加一条 `QARecord(question="fork", answer=<parent_session_id>, source="fork")`（血缘可追溯）。
  - **变更历史**：源 `ChangeRecord` 列表复制进新会话 `inherited_changes`（只读）；新会话 `ChangeHistory` 从 v1 重新计。
  - **账本与预算**：新会话 `TokenLedger` 空账本，`budget` 默认=源会话 budget；`inherited_tokens=源账本 total()` 仅用于成本归因展示——不计入新账本、不双计项目聚合。
  - **记忆**：不复制；新会话读同一项目记忆库（§4.3 共享只读）。
- **事件**：源会话事件日志追加 `session.forked`（payload 含新 sid）；新会话发 `session.start`。

### 8.2 worktree 默认开启规则（唯一结论）

- 判定（`SessionManager.start` 内）：
  1. 项目内已有 `running/waiting_approval` 会话 → 新会话**默认自动启用** worktree（spec 缺省 `worktree=true` 即此语义）；显式 `worktree=false` 且存在并发运行会话 → **400 + code `conflict`**（禁止共享主工作区写）。

- 收尾：会话完成 → `merge_back` 合并回主工作区并移除 worktree；**合并冲突 → 保留 worktree 现场**、会话 `completed` 且 `merge_conflict=true`、发 `worktree.merge_conflict` 事件（详情页人工查看/处理）；aborted/cancel → 丢弃 worktree 不合并。
- 主工作区是唯一集成点：并发会话不直写主工作区（写入边界见 §4.3）。
## 9. 门策略：自动 reviewer（决策 14）

- **配置载体**：`GatePolicyConfig`（§3.1）内嵌 project.json，经 `PATCH /projects/{pid}` 局部覆盖；未知门类别名 → 400 且回退默认策略（配置错误不破坏运行）。
- **判定规则集（每 gate 节点按序，唯一结论）**：
  1. `node.gate ∈ human_kinds` → 恒人工 interrupt（v0.5 ask 行为）；`dangerous_tool/evolution_apply` 保持 bypass-immune 缺省语义，`--yes` 自动拒绝（红线不变）。
  2. `auto_review=False` → 全部回到人工（v0.5 行为，向后兼容开关）。
  3. `node.gate ∈ auto_kinds` → 自动评审：调用 `judge` 模块 LLM 评审（提示词 `review_prompt` 可覆盖），返回 `accept/reject/edit` + 置信度：
     - `accept` → 落 `ApprovalRecord(by_role="auto")` 放行（on_accept 路由）；
     - `reject/edit` → 同门 `rejections += 1` 走返工路由（on_reject/on_edit）；
     - 置信度 < `review_confidence_threshold` → 升级人工（视为边界动作）；
     - deterministic 模式（无模型）→ 自动评审直接 accept 并审计 `source="deterministic-accept"`（演示/测试专用语义，保证无人值守 e2e 可跑通）。
  4. 默认白名单 `design_review/code_review/iteration_acceptance`（常规变更自动评审）；默认黑名单 `requirement_confirmation/release/dangerous_tool/evolution_apply`（恒人工）。
- **边界升级人工的触发条件（唯一清单）**：(a) 黑名单门；(b) 自动评审置信度不足；(c) 同门 reject/edit 累计 ≥ `rework_escalation`（与 v0.5 返工上限同一升级路径）；(d) 项目预算硬上限命中（§5.2）；(e) `unlock_requires_approval` 的解锁请求。其余一律不打扰人工（对标 OpenAI Auto-review：人工审批次数大幅下降，综合调研 §7）。
- **兼容策略**：`SessionDriver` 新增 `gate_policy: GatePolicyConfig | None = None`（缺省 None = 关闭自动评审，v0.5 行为逐字节一致）；`_gate_response` 仅在决策分支扩展；`make_gate_handler / resolve_auto_response / approval_pending` 的既有签名与语义不改。

## 10. 看板 UI（决策 13）

### 10.1 三轴指标定义（唯一计算式）

- **成本轴**：`used = Σ 项目会话 ledger.total()`；`limit = budget_pool.hard_limit_tokens`；`ratio = used/limit`（limit=0 → ratio=0）；`cost_score = max(0, 1-ratio)`；`estimated_usd` 由 CostLedger 聚合。状态：`ratio >= warn_ratio` → warn；`ratio >= 1` → critical；否则 ok。
- **进度轴**：每会话 `phase_ratio = |{p.status == "done"}| / |phases|`（phases 为空时：completed→1，其余→0）；`progress = mean(phase_ratio)`。状态：`≥0.7` ok、`≥0.4` warn、否则 critical。
- **健康轴**：每会话复用 `compute_health` 四指标（eval 通过率趋势 / token 成本 / 预估准确率 / 返工率），None 指标跳过不参与平均；`health = mean(可用会话健康分)`；任一会话 `over_budget` 或 `rework_rate ≥ 0.5` → critical。
- 输出契约：`GET /projects/{pid}/dashboard` → `{cost:{used,limit,ratio,score,status,estimated_usd}, progress:{score,status,phases:{total,done}}, health:{score,status,sessions:{<sid>:{...}}}, updated_at}`；三轴状态枚举统一 `ok|warn|critical`。

### 10.2 任务面板组件与 API 接线

- **组件**：`ProjectSessions` 页升级为任务面板（**不新增第 11 页**）：顶部三轴卡片（复用 Statistic 卡样式）+ 筛选器（状态/指派/关键词，映射 `?status=&assignee=&q=`）+ 会话卡片（指派 Select → `PATCH /projects/{pid}/tasks/{sid}`）+ 新建/派生会话入口；`Dashboard` 全局页追加「项目三轴概览」汇总块。
- **状态管理**：新增 `frontend/src/store/projectStore.ts`（zustand：`dashboard/tasks/filters/loading`，actions `loadDashboard/loadTasks/setFilter/assignTask`）；`appStore` 仅追加 `locale`（§12）；`sessionStore/sseReducer` 接入 `session.end` 哨兵与 seq 去重（§6.3）。
- **路由**：保持 10 页路由不变（`/projects/:pid/sessions` 承载面板）。

## 11. 实时 stdin 注入（决策 4/16：三入口 + 写入 transcript/PRD）

- **语义**：把 v0.5 的 `inject_change`（需求变更）实时化并扩展出独立的「stdin 注入」通道：注入内容作为**用户输入**写入 transcript/PRD（不是需求变更记录）。两通道并存：`/interrupt`=需求变更（行为不变），`/stdin`=实时输入。
- **消费规则（唯一结论）**：`SessionDriver.inject_stdin(text)`（线程安全队列）在**下一个挂起点/门等待点**被消费；若此刻正有 pending prompt 等待答案，stdin 行**优先作为该 prompt 的回答**消费（等价 response，避免挂死）；否则作为自由输入在下一节点边界注入。已终态/已取消会话拒绝注入（409 + code `session_busy`）。
- **写入规则（每条注入，不抛异常阻断）**：
  1. `transcript` 追加 `QARecord(question="[stdin]", answer=text, source="stdin", node=current_node)`；
  2. `ChangeHistory.record(text)` 版本+1（快照）；
  3. 工作区存在 `docs/PRD.md` → 追加小节 `## 补充输入（v<n>）` + 原文（PRD 写入）；不存在则不新建文档（只落 transcript/变更历史）；
  4. 发 `stdin.applied` 事件。
- **三入口（同一权威链路）**：
  1. **serve 端点**：`POST /api/v1/sessions/{sid}/stdin` `{text}` → 202；
  2. **面板**：会话详情页顶部「实时输入」输入框（运行中可用），提交走同一端点（`endpoints.stdinSession`）；
  3. **CLI 管道**：新子命令 `agent-cluster stdin <sid> [--text <text>] [--port 8765] [--auth-token <t>]`——无 `--text` 时读 stdin 至 EOF、每行一条注入；经本地 serve REST 中转（三入口共用一条注入链路）。`build` 单机模式不新增 stdin 参数（其终端交互即 v0.5 prompt 行为，契约不变）。

## 12. i18n（决策 20）

- **技术方案**：FormatJS `react-intl` + ICU MessageFormat + **未编译 JSON 目录**（规模下直接加载，不引 babel 编译链）。`defaultMessage` 一律英文；`id` 命名 `<page>.<component>.<token>`（kebab-case）。
- **目录**：`frontend/src/i18n/messages/en-US.json`（源语言，与 defaultMessage 一致）、`zh-CN.json`（当前语言）。
- **覆盖范围**：10 个页面 + 全部组件（含 AntD 空态文案、错误提示）全量 key 化。**en-US 100% 完整、zh-CN 保持 100%**：新增 `npm run i18n:check`（Node 脚本比较两 JSON 的 key 集合，缺 key/多 key 即退出 1），挂入 Vitest 与 CI frontend job。
- **语言切换**：Settings 页新增「语言 / Language」Select（zh-CN/en-US）；`appStore` 新增 `locale: "zh-CN" | "en-US"`（默认 zh-CN——现有体验不变，persist 持久化）；`App.tsx` 按 locale 切换 AntD `ConfigProvider locale`（`antd/locale/en_US`）并同步 `document.documentElement.lang`。不做实验门控（Codex i18n 教训，综合调研 §3）。
- **后端不译边界（唯一结论）**：REST `error` 字符串与 CLI 输出保持中文；前端按错误 `code` 字段查表本地化（§6.1），无 code/未知 code 时原样展示后端文本；后端不做 gettext/语言参数——错误码即接口。

## 17. 开放问题清单

**结论：无开放问题。** 本文所有设计点均已裁定。曾存在分歧的候选一律按 27 项决策取唯一结论，理由如下：

- Linux 单格式：deb 与 AppImage 二选一 → **取 deb**（决策 17 允许任选；综合调研 §3：Cursor/Claude Desktop 均以 deb 起步，且「单一格式出构建物」要求最省）。
- WebSocket 传输实现：引入 websockets 依赖 vs 自研 → **自研最小 RFC 6455**（与 ThreadingHTTPServer 同进程同认证、零新依赖，符合本项目 stdlib 服务架构；WS 仅产品内通道，不需要 MCP 级传输特性）。
- fork 源会话状态：允许运行中 fork vs 仅终态 → **仅终态**（运行中 checkpoint 非稳定态，409 保护；checkpoint 复制策略由此唯一确定）。
- 自动评审在 deterministic 模式下的行为：回退人工 vs accept → **accept 并审计**（deterministic 仅演示/测试用途，回退人工会破坏无人值守 e2e）。
- 迁移的记忆/checkpoint 策略：移动 vs 复制合并 → **复制合并 + 源文件保留**（无损与幂等优先）。
- i18n 默认语言：en-US vs zh-CN → **默认 zh-CN**（现有体验不变；决策 20 只要求 en-US 全量 + 可切换）。
