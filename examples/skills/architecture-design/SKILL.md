# 架构设计执行指引

1. 通读 PRD 与需求评审结论，列出设计目标与约束（技术栈自主决策，倾向成熟方案）。
2. 技术选型：按团队熟悉度/生态/部署成本给出取舍表，记录决策理由。
3. 模块划分：前端/后端/算法模块边界、目录结构、依赖方向（依赖倒置）。
4. 接口契约：API 列表（方法/路径/请求响应）、数据结构、错误码；前后端契约先行。
5. 数据模型：实体关系、索引与迁移策略；算法侧给出输入输出规格与评估指标。
6. 非功能需求：性能目标、可观测性、安全基线、部署拓扑。
7. 任务估点：按 token 制（非时间）给开发/测试/文档各任务预估 token 消耗，
   写入设计文档的任务表；落盘 docs/architecture.md 并提交。
